# DeskOrb 评测与测试代码整理设计

## 背景

DeskOrb 的生产 UI、Agent Runtime 和本机真实 E2E runner 都是历史上逐步增长的单体文件。当前功能已经有可用的回归保护，但测试入口、数据集加载和运行产物说明分散在多个文件中，增加了定位失败和维护测试矩阵的成本。

## 目标

- 保留现有命令、模块导入和运行行为；
- 为 60 条 E2E 矩阵建立唯一的数据集加载边界；
- 把测试目录的单元测试、确定性控制组、真实环境探针和质量门禁职责写清楚；
- 让报告、临时浏览器 profile 和桌面夹具的生命周期边界可被维护者快速理解；
- 为后续拆分 `deskorb_agent.py` 或 `local_real_e2e_runner.py` 留出稳定的兼容层。

## 非目标

- 本轮不拆分 Tk UI 单体 `deskorb_agent.py`；
- 不删除旧的探针脚本或运行产物；
- 不改变模型提示、工具编排、安全策略或 E2E 判定规则；
- 不在没有真实桌面/公网授权的情况下扩大测试范围。

## 方案

### 1. 评测数据边界

新增 `tests/e2e_support/datasets.py`，集中维护基础任务集、扩展任务集和路径解析，并提供唯一的 60 条矩阵加载函数。`matrix_e2e_runner.py` 和 `local_real_e2e_runner.py` 保留原来的 `load_matrix_cases()` 作为兼容入口，但委托给共享模块。

### 2. 测试职责边界

保留现有文件位置，先通过 `tests/README.md` 建立分类，不进行一次性大规模移动：

- `test_*.py`：快速单元/集成回归；
- `matrix_e2e_runner.py`：不联网、不接管真实桌面的确定性控制组；
- `local_real_e2e_runner.py`：显式授权后的本机真实链路；
- `*_probe.py`：人工或环境相关探针，不作为默认单元测试；
- `run_quality_gate.py`：只读取脱敏 JSON，执行质量门禁。

这样可以先降低认知成本，再在后续独立切片中移动文件而不破坏外部脚本路径。

### 3. 文档与产物

README 和评测文档只保留当前入口和安全边界；历史执行记录放在 `tasks/`，使用明确日期和“历史记录”标记。`artifacts/` 作为本地运行产物目录，不把运行报告混入源代码模块。

## 兼容性约束

- `python tests/matrix_e2e_runner.py` 和 `python tests/local_real_e2e_runner.py` 继续可直接执行；
- 现有测试对两个 runner 的函数导入继续有效；
- 数据集加载失败仍然 fail closed，并且仍要求 60 个唯一案例；
- 共享模块只使用标准库，不增加依赖。

## 验证

1. 先用测试证明共享 loader 的路径、60 条唯一性和两个 runner 的一致性；
2. 实现共享 loader，运行 focused 测试；
3. 同步测试分类说明与 README 入口，运行全量 `pytest -q`；
4. 对改动做正确性、架构、安全和可维护性审查；
5. 仅在所有验证通过后提交本轮整理。
