# DeskOrb 桌面操作提示层设计

## 目标

当 DeskOrb 真正控制当前 Windows 桌面时，向本机用户提供持续、明确且不干扰操作的视觉提示：屏幕四周出现自然的羽化虚化效果，顶部中央显示“DeskOrb 正在操作你的电脑”。模型思考、观察界面、读取文件和只读联网分析期间不显示。

该功能必须满足三个硬性条件：不抢占前台窗口焦点、不截获鼠标或键盘输入、不出现在 DeskOrb 提供给模型的桌面截图中。

## 触发范围

提示层只包围已经通过安全策略且即将实际执行的本机桌面动作：

- `application_launch`
- `desktop_click`
- `desktop_type`
- `desktop_hotkey`
- `desktop_scroll`
- `window_focus`
- `window_control`

以下活动不触发提示：模型推理、工具选择、等待授权、策略拒绝、窗口枚举、截图、桌面状态验证、剪贴板读取、文件操作、Shell 操作、浏览器只读研究和其他 MCP 调用。高风险动作只有在用户确认后、真正开始执行时才触发。

## 方案选择

采用“专用运行时事件 + 独立提示层”的方案。`AgentRuntime` 在实际桌面动作前后发布专用事件，Tk 主线程根据事件驱动动画。该方案比从现有工具文案推断状态更可靠，能够在失败和异常路径中保证收尾；也比整个任务期间显示更准确，不会把模型思考误报成桌面控制。

事件不包含工具参数、坐标、输入文字或窗口标题，只包含工具安全名称和进程内递增的活动编号：

```text
desktop_activity { phase: begin|end, tool: <safe tool name>, activity_id: <integer> }
```

## 组件边界

### `agent_runtime.py`

新增一个仅负责仪表化桌面动作的包装方法。它在调用 `_run_local_tool` 前发布 `begin`，并在 `finally` 中发布 `end`。普通工具循环和确认后继续执行路径都必须使用该包装方法，防止异常、取消或已确认动作绕过生命周期事件。

策略拒绝和等待确认不会进入包装方法，因此不会错误显示提示层。事件发布失败不得阻断工具执行。

### `desktop_activity_indicator.py`

新增独立模块，包含两个职责清晰的单元：

- `DesktopActivityLifecycle`：管理 `hidden`、`entering`、`visible`、`exiting` 状态，负责最短显示时间、空闲延迟、连续动作合并和过期定时器失效；不依赖具体 Win32 绘制，便于单元测试。
- `DesktopActivityIndicator`：创建、布局、动画和销毁提示窗口；只在 Tk 主线程调用，通过 `after` 调度动画，不创建动画线程，也不使用阻塞式等待。

### `deskorb_agent.py`

在 `Overlay` 初始化时创建提示层，在 `_poll` 中消费 `desktop_activity` 事件；`turn_done`、停止、错误、人工验证、等待授权和应用退出路径执行幂等的强制隐藏或销毁。显示失败只记录诊断信息，不影响聊天和工具执行。

### `win32utils.py`

复用现有 `enumerate_monitors`、DPI 和 `WDA_EXCLUDEFROMCAPTURE` 能力，并增加小型窗口样式助手，为每个提示窗口设置：

- `WS_EX_TRANSPARENT`：鼠标事件穿透；
- `WS_EX_NOACTIVATE`：显示和置顶时不激活；
- `WS_EX_TOOLWINDOW`：不出现在任务栏和 Alt+Tab；
- `HWND_TOPMOST` 配合 `SWP_NOACTIVATE`：保持可见但不改变前台焦点；
- `WDA_EXCLUDEFROMCAPTURE`：不污染模型截图和屏幕状态摘要。

所有样式设置必须在窗口显示前验证。鼠标穿透、禁止激活或截图排除任一关键能力失败时，本次会话禁用提示层并返回诊断结果，不能以可能阻断用户输入或污染模型视觉证据的方式降级。

## 视觉与动画

每台已连接显示器创建四个窄边缘窗口和一个顶部提示胶囊。边缘窗口只覆盖显示器外围约 60 个逻辑像素，中心区域不存在覆盖窗口。优先启用 Windows DWM 原生背景虚化；系统不支持时使用低透明度羽化暗边作为视觉降级，窗口交互和截图安全条件保持不变。

固定提示文案为：

```text
DeskOrb 正在操作你的电脑
```

动画参数：

- 淡入 200ms，使用 ease-out；边缘透明度由 0 增至最多约 24%；
- 胶囊同时从目标位置上方 8 个逻辑像素滑入；
- 最短可见时间 450ms，避免快速动作一闪而过；
- 动作结束后保留 300ms 空闲窗口；期间有新动作则取消退出并保持可见；
- 淡出 280ms，使用 ease-in-out；
- 动画帧间隔约 20ms，使用单调时钟计算进度，慢帧不会累积漂移；
- 状态点使用约 900ms 的低频呼吸变化，不使用闪烁。

连续桌面动作共享同一提示周期。开始新动作时，退出动画可从当前透明度平滑反转为进入动画，不能先隐藏再重建。显示器增删、分辨率或 DPI 改变时，在下一次安全状态刷新布局；正在执行动作时保持现有窗口，动作结束后重建，避免操作中闪跳。

## 数据流和生命周期

```text
模型选择工具
→ 安全策略允许或用户确认
→ runtime 发布 desktop_activity.begin
→ UI 淡入提示层
→ 执行本机桌面动作
→ runtime 在 finally 发布 desktop_activity.end
→ UI 等待最短显示时间和 300ms 空闲窗口
→ 没有后续动作时自然淡出
```

生命周期按 `activity_id` 配对开始和结束事件，并使用独立的动画代次标识使旧的 `after` 回调自动失效。相同活动的重复 `begin` 是幂等的；未知、重复或迟到的 `end` 会被忽略，不能把一个更新的活动周期提前关闭。强制隐藏会清空活动编号集合，取消全部动画与延迟回调，并把透明度和窗口映射状态恢复到确定的隐藏状态。

## 错误和安全处理

- `_run_local_tool` 抛出异常时，`finally` 仍发布 `end`。
- UI 事件延迟或乱序时，代次标识忽略过期退出回调。
- 提示窗口创建、DWM、Win32 样式或截图排除失败时，销毁已创建的全部提示窗口，并在本次进程内禁用该功能。
- `turn_done`、运行时错误、停止、人工验证、等待授权、窗口关闭和进程退出均强制隐藏或销毁。
- 提示层不展示动作参数、用户输入、目标窗口标题、网址或任务内容。
- Windows UAC 安全桌面不允许普通进程覆盖；提示层不会尝试跨越该安全边界。

## 测试设计

### 单元测试

- 只有七种本机桌面动作触发 `begin/end`，观察和非桌面工具不触发；
- 策略拒绝和等待确认不触发，确认后实际执行触发；
- 成功、返回失败和抛出异常都产生配对的结束事件；
- 450ms 最短显示、300ms 空闲合并和 280ms 淡出按单调时钟工作；
- 连续动作不会中途隐藏，退出中的新动作会平滑恢复；
- 活动编号正确配对，迟到回调、未知或重复结束、强制隐藏和销毁保持幂等；
- Win32 关键样式或截图排除失败时 fail closed，不保留任何可见窗口；
- 事件和日志中不包含工具参数或用户文本。

测试使用假的时钟、调度器、窗口和 Win32 适配器，不要求真实桌面即可稳定运行。

### 集成和真实桌面验收

1. 运行相关测试和完整 pytest 套件。
2. 在临时记事本中串行执行启动、聚焦、点击、输入、快捷键和滚动。
3. 验证提示自然淡入、连续动作无闪烁、最终自然淡出。
4. 验证记事本始终保持前台焦点，鼠标可穿过边缘和胶囊区域。
5. 在提示可见时执行 DeskOrb 桌面截图，确认图片中没有提示层。
6. 模拟工具失败、用户停止和应用退出，确认没有残留顶层窗口。
7. 多显示器存在时验证每台显示器边缘布局；单显示器环境至少验证分辨率变化后的重建。

## 完成标准

- 用户只在 DeskOrb 真正操作桌面时看到提示；
- 四周羽化效果和顶部胶囊过渡连续、无明显闪烁或跳变；
- 提示层不改变前台焦点、不截获输入、不出现在模型截图中；
- 所有结束和异常路径都不残留窗口；
- 新增测试、现有桌面测试和完整测试套件全部通过。
